# Field drafts and explicit reconnection

An inspector or administrator can record findings in the Evidence Passport's Take action tab. Notes remain in memory until device storage is enabled. With “Keep these notes on this device” enabled, every edit saves notes, the three checklist choices, the original case version and any pending submission in a versioned record. Storage keys include the signed-in account and case ID. Existing plain-text drafts restore with unchecked checklist choices. Account separation is an application behavior, not device encryption.

The already-loaded page supports offline editing. It shows the browser's network status and disables submission while offline. Returning online does not send anything: the user must choose Submit inspection, Submit follow-up, Submit intervention or Retry pending submission. Switching Evidence Passport tabs preserves in-memory notes. Device-saved drafts restore when the case is reopened or the page is reloaded with the local service available. Storage failures are displayed without falsely reporting a saved device copy.

Before submission, the client freezes its payload and creates a submission identifier. With device storage enabled, the pending payload is saved before sending. If the network drops before confirmation, the exact notes, checklist, version, kind and identifier remain pending, and editing is locked. Retry sends that same request. Inspection and intervention endpoints use the existing evidence submission unique index scoped to case and actor. An already-committed matching request returns the current authorized case without new evidence, audit, notifications or version increment. A reused identifier with different content is rejected. Permission and scope checks apply even to retries. No schema migration is needed.

A stale case version is rejected without publishing evidence. Refresh case for review updates the Evidence Passport; Use reviewed case version explicitly retains the notes while preparing a new attempt against the reviewed version. This is not an automatic overwrite. Follow-up/intervention state restrictions continue to apply. Evidence is marked synchronized only after a successful server response; device cleanup happens after confirmation. Case-list refresh is separate from evidence confirmation.

Verification injects offline browser state, reloads a saved draft after reconnect, commits an inspection while dropping its response, reloads and retries the pending submission, creates a concurrent case-version change, and switches accounts on the same browser. It checks exact evidence/audit counts, retained notes/checklists, explicit review and storage separation. API tests additionally verify mismatched-key rejection and permission revocation. Draft parsing tests cover legacy notes, pending payload restoration and invalid records.

Limits: the browser network indicator does not prove server reachability; request errors remain authoritative. Inspector and administrator workspaces still require the local server after reload. The service worker caches only a citizen report entry; offline inspector workspace is not included. Reopening a field case still requires the server. Only consented device copies survive a closed tab. Photo uploads, cross-device sync and simultaneous editing of the same draft in multiple tabs are outside this verification. Notes stored on a shared device can be cleared from Preferences. No background synchronization is performed.
