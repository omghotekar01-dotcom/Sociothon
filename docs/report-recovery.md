# Citizen report draft and receipt recovery

The report wizard supports English and Marathi connectivity, saved-draft and pending-submission messages. An already-loaded page remains editable while offline. Submission is disabled until the browser reconnects; reconnection never sends a report automatically.

Save unsent draft opts into device storage for the current account. Further changes, the wizard position and pending state are then saved automatically. Location is omitted by default. The separate location checkbox explicitly enables retaining it; switching it off removes it from subsequent device snapshots. Restoring a normal redacted draft returns to the location step. Legacy drafts remain readable; malformed or unsupported records are preserved and show an error until explicitly cleared. Storage errors do not claim successful persistence.

Submission keeps the original idempotency key. When a response is missing or uncertain, category and description are locked. A saved pending draft survives reload. Check submission status uses an authenticated, owner-only lookup (`GET /api/v1/reports/submissions/{submission_key}`), returning either the original report/receipt or a null report. Other users, including staff, cannot discover someone else's receipt by knowing that key.

Retry same report first performs this lookup. If the server already committed the report, the receipt is restored without another POST, even when the device did not retain location. If no report is found, the user can re-enter the original location and explicitly retry with the same identifier. The existing API rejects mismatched content and prevents duplicate reports, cases and reported-audit entries. A confirmed receipt remains authoritative even if the workspace refresh or local cleanup fails. Confirming a new unsaved report does not remove an unrelated saved draft.

Verification injects offline state, restores a Marathi draft with redacted location, drops a response after the server commits, aborts another request before commit, and retries after re-entering the location. It checks exact report counts, matching receipt identifiers, absence of another POST during recovery, location opt-in, malformed-draft retention and mobile overflow. API tests verify receipt consistency and owner-only lookup. Draft tests cover privacy defaults, pending identifiers and legacy/invalid formats.

Limits: the cached citizen entry was verified after an earlier online visit with explicit offline readiness. The first-ever visit still needs connectivity and the inspector workspace remains online-only. Without saving a device draft, pending state lasts only in the open page. Device storage is account-keyed application storage, not encryption. Private photo uploads have a separate verified connection-recovery workflow; see photo-recovery.md. Concurrent editing of one draft across browser tabs is not coordinated. This is a local synthetic demonstration, not an emergency reporting service.
