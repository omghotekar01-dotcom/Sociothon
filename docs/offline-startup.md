# Offline citizen reporting startup

After an online visit, the root-scoped service worker caches the application shell and its versioned frontend assets. It uses network-first navigation and static asset requests, with the cached shell and assets as an offline fallback. All `/api/` requests bypass the cache. Account sessions, bootstrap responses, reports, photos and other API data are not stored by the service worker.

In the citizen report page, the user can explicitly enable “Keep citizen reporting ready on this device for offline use”. The device retains only that account's internal identifier and language setting. This is not a credential and does not allow offline authentication. If the server cannot be reached while opening the app, the cached shell shows a local draft entry. With the opt-in, an existing saved report draft can be restored or a new report can be edited and saved. Submit and status-check controls remain disabled in this entry. The user must reconnect, sign in normally and submit the saved report explicitly.

Turning off offline readiness removes its local identifier. Signing out also removes it. Previously saved report drafts remain under their separate explicit save preference and are not erased by disabling offline readiness.

The cache is populated only after visiting the app while online. It cannot make the first-ever visit work without a network, and it does not cache authenticated data or report tracking screens. The offline entry is limited to the citizen report wizard. A two-stage Edge check used a fresh persistent profile: it installed the worker, confirmed the shell and frontend assets were cached, saved a synthetic consented draft, closed the browser, stopped the local server, and opened a new page directly at `/network`. The cached shell appeared, the draft restored for editing, and submit stayed disabled with no uncaught page errors. The expected API session request failed while the server was stopped. Evidence is in `artifacts/verification/offline-startup-results.json`; screenshots are `offline-startup-online-390.png` and `offline-startup-restored-390.png`.

Reproduce with the local app running: `node scripts/offline-startup-check.mjs prepare`, stop the server, then run `node scripts/offline-startup-check.mjs offline` with the same `CIVIC_OFFLINE_PROFILE` and `CIVIC_BROWSER_PATH`. Restart the app afterward. This covers a browser with an existing service-worker cache and opt-in; first-ever offline use remains impossible by design.
