# Seven-minute demonstration

Use synthetic demo accounts only. All accounts use `CivicDemo!2026`; role emails are listed in README. The application is a local hackathon prototype, not an official civic or emergency service.

| Time | Action | Explain |
| --- | --- | --- |
| 0:00–0:45 | Enter the observatory, select Latest water readings on the timeline, then open the water workspace. | Three synthetic zones, real computed readings and explicit provenance. The map is schematic. |
| 0:45–1:30 | Open a water finding's Evidence Passport and export JSON. | Historical baseline, quality, alternatives and auditable decisions support investigation; a flag is not proof of a leak. |
| 1:30–2:15 | Run the overnight-leak scenario in Scenario Studio. Wait for a succeeded job, then play, pause or step through its recorded results. | Baseline and counterfactual are stored separately. Synthetic intervention effects do not close real work orders. |
| 2:15–3:00 | Show the forecast and tank projection. | Forecast uncertainty, holdout errors and storage conservation; no hydraulic claim. |
| 3:00–4:00 | Sign in as citizen, choose Marathi, submit a clearly labelled demo report and download its receipt. Open tracking. | Report persistence, account privacy, localized tracking and human review. |
| 4:00–5:30 | Use operator review and assignment, then inspector inspection/intervention and monitoring. Record follow-up, then return to operator for resolution. | The server rejects skipped steps and inspector closure. Allow extra time for account switching; do not claim this entire sequence was rehearsed in seven minutes. |
| 5:30–6:15 | Inspect connected-domain suggestions and the impact screen. | Proximity is a lead; administrative resolutions and estimated excess are not certified repairs or causal savings. |
| 6:15–7:00 | Show method evaluation and limitations; reset only the selected scenario run if desired. | Held-out metrics are synthetic, actual false positives are visible, and user evidence survives reset. |

For secondary demonstrations, run electricity sustained excess or voltage fluctuation, roads budget planning, drainage rainfall/blockage, waste capacity, streetlight failure, or general damage. Each uses the same accountable human case workflow with domain-specific computed evidence. The API suite exercises full lifecycle transitions for all seven domains; a complete timed browser rehearsal is still pending.

Before presenting, build the frontend, start API and worker, open the intended views once, and confirm the required demo accounts. Startup/dependency installation needs preparation; runtime browser checks deny external requests. Recorded playback has pause, step, speed and reset controls. The worker can pause queued scenarios or save a running calculation at its publication checkpoint; it does not interrupt individual numerical operations. Water and electricity baselines can be promoted and rolled back from the Model & Sensor Lab. These controls preserve human decisions.
