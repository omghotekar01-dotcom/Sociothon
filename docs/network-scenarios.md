# Water network closure sandbox

The Network explorer renders the stored, authorized water topology. Arrows represent directed pipes and configured lengths; the schematic coordinates are illustrative. Select a node or an asset-register entry to inspect its identity and authorized cases, then choose it as a source or target.

Investigation overlays add a numbered ring to assets with open, linked water cases. The number counts distinct cases; the ring shows the highest recorded open-case severity. Resolved and closed cases do not contribute. Cases must match both asset ID and zone; unlinked nearby reports are not attached by proximity. Counts are limited to the authorized cases supplied by the API and the visible network zone. Hiding markers changes the display only and leaves case counts and paths unchanged. A node without a marker does not establish normal service.

The selected-asset panel lists open case titles, recorded severity, workflow status, provenance, last-update time and summaries. Choose a card to open the existing authorized Evidence Passport and its export. Include resolved and closed cases to review history. Marker counts update when refreshed case data changes, including human closure or reopening; network scenarios themselves never change those decisions. The asset register provides equivalent textual counts and severity for keyboard and mobile use.

Zoom controls enlarge the diagram from 100% to 300% inside a scrollable region, without changing path or investigation data. Scroll to pan, or use Fit network diagram to restore the original scale. The scroll region is keyboard-focusable.

Select a pipe on the diagram, press Enter or Space while it has focus, or use its closure-register checkbox to close or reopen it in the scenario. The API recalculates the shortest directed path and downstream reachable assets. Cyan edges identify that path; closed pipes are dashed and marked with a cross. A disconnected target has no path or distance, rather than an invented impact estimate. A source equal to the target has a zero-length path. Configured closed pipes remain closed and cannot be reopened by this local scenario.

The zone filter restricts both the diagram and calculation to nodes and pipes inside the selected zone. Paths cannot traverse hidden or unauthorized zones. Changing zone, choosing Reset network scenario, reloading or leaving the page restores the configured topology; these are temporary page controls, not persisted worker jobs. Export network scenario downloads the selected inputs, computed result, provenance and limitation as JSON.

`POST /api/v1/network/path` accepts `source`, `target`, optional `closed_edges` and optional `zone_id`. It calculates against the stored configuration after authorization and zone filtering, not a separate hard-coded topology. Unknown or out-of-view closures are rejected. The response includes ordered `path` and `path_edges`, configured `distance_m`, downstream `reachable`, `unreachable` and effective `closed_edges`. The source itself is excluded from both downstream sets. The request performs no database writes: cases, assets, connection configuration and other users' scenarios are unchanged.

The sandbox does not operate physical valves or infer hydraulic pressure, delivered volume, supply loss, fault location or customers affected. Those questions require additional data and a hydraulic model. Persistent named topology scenarios and a geographic network editor are outside this implementation. Investigation markers reflect recorded cases, not independent sensor-health or live hydraulic measurements.

Verification covers alternate-route selection, isolation, directed reverse paths, same-node paths, configured closure, reopening, reset, database configuration use, citizen rejection, restricted-zone traversal and zone filters. Browser checks exercise keyboard interaction, SVG and table synchronization, export, reset/reload, unchanged cases and configuration, and 390/768/1440-pixel layouts.
